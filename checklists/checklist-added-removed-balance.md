# Чек-лист: баланс added/removed строк кода

Используется, когда метрики показывают сильный перекос в сторону "added" при почти нулевом "removed". Помогает встроить рефакторинг в рабочий процесс, а не откладывать его "на потом".

## 1. Закладывать рефакторинг как отдельную задачу
- [ ] Заводим тикеты/PR с явной пометкой `refactor:` или `cleanup:`
- [ ] Правило: на каждые N фич-PR — один рефакторинг-PR (например, раз в спринт)

## 2. Использовать Claude Code для рефакторинга целенаправленно
- [ ] Отдельные сессии с промптом "проанализируй модуль и предложи, что удалить/упростить/объединить"
- [ ] Просим Claude искать мёртвый код, дублирование, неиспользуемые импорты перед добавлением новых правок

## 3. Правило бойскаута (Boy Scout Rule)
- [ ] При правке кода рядом — немного улучшаю: убираю мёртвый код, переименовываю неясные переменные, разбиваю длинные функции
- [ ] Это не отдельная задача, а часть обычной работы над фичей

## 4. Регулярный аудит мёртвого/дублирующегося кода
- [ ] Раз в месяц/квартал прогоняю статический анализ (unused exports, dead code detectors, jscpd и подобное под свой стек)
- [ ] Завожу тикеты на найденное
- [ ] Смотрю на файлы, которые только растут и никогда не сокращаются — это кандидаты на пересмотр

## 5. Пороговые значения как триггер к рефакторингу
- [ ] Если файл/функция превышает порог (например, 300-500 строк или высокая цикломатическая сложность) — останавливаюсь и разбиваю/чищу вместо того, чтобы дописывать сверху

## 6. Отслеживать churn, а не только added/removed
- [ ] Смотрю `git log --stat` по файлам за период — какие меняются чаще всего
- [ ] Часто изменяемые файлы — кандидаты на рефакторинг в первую очередь

## 7. Честно разделять стадии проекта
- [ ] Если проект молодой — added >> removed нормально, рефакторить пока нечего
- [ ] Если проект зрелый (месяцы/годы в проде) и паттерн тот же — закладываю отдельные "техдолг-спринты"

## 8. Rewrite-сессии как отдельный тип работы
- [ ] Периодически прошу Claude Code не "добавить фичу", а "перепиши этот кусок чище, сохранив поведение"
- [ ] Обязательно закрываю такие сессии тестами на регрессию
