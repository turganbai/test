# Чек-лист: размер файлов/функций и цикломатическая сложность как триггер рефакторинга

Используется, когда нужно превратить субъективное "тут пора почистить" в объективный, измеримый и автоматизируемый триггер.

## 1. Выбрать пороги под свой стек
- [ ] Смотрю медиану размера файлов/функций по текущей кодовой базе (не беру число "из интернета")
- [ ] Стартовые ориентиры: 300-500 строк на файл, 30-50 строк на функцию, цикломатическая сложность 10-15 на функцию
- [ ] Фиксирую пороги в конфиге линтера, а не в голове/договорённости на словах

## 2. Начать с предупреждения, не с блокера
- [ ] На существующей кодовой базе включаю пороги как warning в CI, не как hard fail
- [ ] Собираю статистику: сколько файлов/функций уже превышают порог
- [ ] Только после приведения базы в порядок перевожу проверку в блокирующую

## 3. Разделить правила для нового кода и legacy
- [ ] Новый код обязан соблюдать порог сразу
- [ ] Legacy-код чищу по мере правок (правило бойскаута), не отдельным марафоном

## 4. Встроить в pre-commit/CI
- [ ] Проверка сложности и размера запускается автоматически на каждый PR
- [ ] Не полагаюсь на ручную дисциплину/память команды

## 5. Приоритизировать по пересечению "сложно + непокрыто тестами"
- [ ] Смотрю сложность вместе с покрытием тестами по тем же файлам/функциям
- [ ] В первую очередь рефакторю то, что одновременно сложное и без тестов

## 6. Использовать Claude Code для самого разбиения
- [ ] При срабатывании триггера прошу разбить функцию на мелкие части с сохранением поведения и понятными именами шагов
- [ ] Прогоняю существующие тесты как regression-check после разбиения

## 7. Не делать порог самоцелью
- [ ] Проверяю, не отражает ли высокая сложность реально сложную бизнес-логику (например, edge-кейсы в расчётах)
- [ ] В таком случае — не разбиваю ради цифры, а рассматриваю альтернативы (таблицы решений, явные тест-кейсы) вместо искусственного дробления

## 8. Команды и инструменты — PHP

**Цикломатическая сложность и размер**
```bash
# PHP Mess Detector (PHPMD) — сложность, размер методов/классов
composer require --dev phpmd/phpmd
vendor/bin/phpmd src/ text cleancode,codesize,design

# PHPStan с правилом на сложность (через расширение)
composer require --dev phpstan/phpstan
vendor/bin/phpstan analyse --level=6 src/

# phpcs с правилами на длину функций/файлов (PSR + Generic.Metrics)
composer require --dev squizlabs/php_codesniffer
vendor/bin/phpcs --standard=Generic src/
```

## 9. Команды и инструменты — Go

**Цикломатическая сложность**
```bash
# gocyclo — классический инструмент для расчёта цикломатической сложности
go install github.com/fzipp/gocyclo/cmd/gocyclo@latest
gocyclo -over 15 .

# golangci-lint с линтерами gocyclo/gocognit
golangci-lint run --enable=gocyclo,gocognit
```

**Размер функций/файлов**
```bash
# funlen — линтер на длину функций (обычно через golangci-lint)
golangci-lint run --enable=funlen

# dupl для параллельной проверки на дублирование при рефакторинге
go install github.com/mibk/dupl@latest
dupl -threshold 50 ./...
```
