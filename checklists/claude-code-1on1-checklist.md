# Чек-лист для 1-on-1: обсуждение работы разработчика с Claude Code

Порядок просмотра метрик перед разговором — от общей картины к деталям.

## Шаг 1. Общая активность (масштаб использования)

- [ ] `distinct_session_count` — сколько сессий за период
- [ ] `active_days` — в скольки днях вообще был активен
- [ ] Сравнить с командой: это средний уровень, выше или ниже?

**Вопрос, если сильно ниже команды:** "Что мешает пользоваться чаще — задачи не подходят, или не привык встраивать в процесс?"

## Шаг 2. Выход в реальный код

- [ ] `commit_count` — сколько коммитов через Claude Code
- [ ] `pull_request_count` — сколько PR
- [ ] Соотнести с `distinct_session_count`: много сессий, мало коммитов?

**Вопрос:** "Вижу много сессий, но мало коммитов — где обычно застреваешь?"

## Шаг 3. Объём и характер изменений

- [ ] `lines_added` vs `lines_removed`
- [ ] Сильный перекос в сторону added без removed?

**Вопрос:** "Не копится ли долг — есть время на рефакторинг того, что уже написано с Claude?"

⚠️ Помнить: эта метрика не отслеживает последующие удаления — не абсолютная истина.

## Шаг 4. Качество взаимодействия (accept/reject)

- [ ] `suggestion_accept_rate` по Edit / Write / NotebookEdit
- [ ] Сравнить с обычным для похожих типов задач (не абсолютный KPI!)
- [ ] Проверить: не работает ли человек в auto-accept режиме (тогда метрика неинформативна)

**Вопрос:** "У тебя много отклонённых правок в последнее время — это сложный код, или Claude не понимает контекст?"

## Шаг 5. Использование возможностей организации

- [ ] `distinct_skills_used_count`
- [ ] `distinct_connectors_used_count`
- [ ] `distinct_projects_used_count` (в чате)

**Вопрос, если низкое:** "Ты знаешь про [skill/коннектор X], который у нас есть для таких задач?"

## Шаг 6. Глубина работы над сложными задачами

- [ ] `thinking_message_count` — использует ли extended thinking
- [ ] `web_search_count` — не тратится ли время на поиск базовых вещей

**Вопрос, если thinking почти не используется:** "На сложных багах пробовал попросить Claude рассуждать шаг за шагом?"

---

## Главное правило разговора

Каждая метрика — повод спросить "что происходит?", а не готовый вывод о качестве работы.
Разные задачи, разные permission-режимы и разный стиль работы дают разные цифры —
сравнивать стоит с самим собой во времени и с похожими задачами, а не как рейтинг между людьми.
