# Чек-лист: регулярный аудит мёртвого и дублирующегося кода

Используется как расширение практики "баланс added/removed" — конкретные шаги и команды для регулярной чистки кодовой базы.

## 1. Встроить в CI, а не делать вручную раз в квартал
- [ ] Детекторы мёртвого кода/дублирования запускаются на каждый PR (хотя бы как предупреждение, не блокер)
- [ ] Раз в месяц/квартал — дополнительный полный прогон по всему репозиторию (не только по diff PR)

## 2. Команды и инструменты — PHP

**Неиспользуемый код (dead code / unused symbols)**
```bash
# PHPStan — статический анализ, включая неиспользуемые приватные методы/свойства
composer require --dev phpstan/phpstan
vendor/bin/phpstan analyse --level=6 src/

# Psalm — похожий анализатор, находит unused code, unused variables
composer require --dev vimeo/psalm
vendor/bin/psalm --find-unused-code

# Rector — может находить и автоматически убирать часть мёртвого/устаревшего кода
composer require --dev rector/rector
vendor/bin/rector process src --dry-run
```

**Дублирование кода**
```bash
# PHP Copy/Paste Detector (phpcpd)
composer require --dev sebastian/phpcpd
vendor/bin/phpcpd src/
```

**Неиспользуемые Composer-зависимости**
```bash
composer require --dev icanhazstring/composer-unused
vendor/bin/composer-unused
```

## 3. Команды и инструменты — Go

**Неиспользуемый код (dead code / unused symbols)**
```bash
# deadcode — официальный инструмент из golang.org/x/tools
go install golang.org/x/tools/cmd/deadcode@latest
deadcode ./...

# staticcheck — включает проверку unused (U1000)
go install honnef.co/go/tools/cmd/staticcheck@latest
staticcheck ./...

# unused (входит в staticcheck, но можно и отдельно через golangci-lint)
golangci-lint run --enable=unused
```

**Дублирование кода**
```bash
# dupl — детектор дублирующихся кусков кода в Go
go install github.com/mibk/dupl@latest
dupl -threshold 50 ./...
```

**Неиспользуемые зависимости в go.mod**
```bash
go mod tidy -v
```

## 4. Разделять "шум" и "сигнал"
- [ ] Настраиваю allowlist/исключения для экспортов, используемых извне (публичный API, DI-контейнеры, рефлексия)
- [ ] Договариваюсь в команде о пороге дублирования (например, от скольки строк считать дублированием критичным)

## 5. Приоритизировать по размеру и частоте изменений
- [ ] Смотрю `git log --stat --since="3 months ago"` — какие файлы меняются чаще всего
- [ ] Начинаю чистку с файлов, которые одновременно большие И часто редактируются

## 6. Тикеты с конкретикой
- [ ] Заводим тикет с конкретным именем функции/файла и фактом "не вызывается с [дата]", а не абстрактное "почистить код"
- [ ] Прикладываю вывод детектора как есть — не пересказываю своими словами

## 7. Отслеживать прогресс аудита
- [ ] Фиксирую не только "нашли N проблем", но и "закрыли N из найденных" за период
- [ ] Если процент закрытия низкий — обсуждаю, не превратился ли аудит в отчёт, который никто не разбирает

## 8. Подключить Claude Code к процессу
- [ ] Раз в месяц прошу Claude Code взять список находок от детектора и предложить безопасные удаления с обоснованием (проверка использования по всему репозиторию, включая динамические вызовы/рефлексию)
- [ ] Каждое предложенное удаление подтверждаю тестами/CI перед мёржем
